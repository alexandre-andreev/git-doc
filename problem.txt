#Решение проблемы авторизации на GitHub при создании нового репозитория 

Сменил remote, чтобы логин был сразу в URL:

bash
git remote set-url origin https://alexandre-andreev@github.com/alexandre-andreev/git-doc.git
Это убрало отдельный запрос Username и оставило только запрос пароля (токена).

Отключил автоподстановку учётных данных в Git (это реально сработало, даже если в Windows ничего не было):

bash
git config --local credential.helper ""
или, если не сработало сразу, вариант с удалением настройки:

bash
git config --local --unset credential.helper
Без этого Git мог пытаться использовать какой‑то локальный кэш или «запомненный» ответ и не показывать нормальный диалог ввода.

Создал новый токен с единственным нужным правом repo — и именно его ввёл во всплывающем окне.

То есть ключ был не в очистке Windows, а в том, чтобы отключить локальный helper в самом Git и дать ему чистый токен с правильными правами.

Чтобы вернуть автоподстановку учётных данных (то есть снова позволить Git брать логин/токен из системного менеджера паролей), нужно просто вернуть настройку credential.helper.

Для Windows (Git for Windows) — самый частый вариант
Выполни в терминале в папке своего репозитория:

bash
git config --local credential.helper manager-core
Почему именно manager-core: это современный помощник в Git for Windows, который как раз и работает с Диспетчером учётных данных Windows.

Если вдруг захочешь включить глобально (для всех репозиториев)
Тогда используй --global вместо --local:

bash
git config --global credential.helper manager-core
⚠️ Лучше использовать --local (только для текущего репозитория). Тогда если в другом проекте захочешь, например, работать через SSH или по-другому — там ничего не сломается.

Как проверить, что всё вернулось
Выполни:

bash
git config --local credential.helper
Если увидишь manager-core — настройка применена. Теперь при git push Git будет сначала смотреть, есть ли сохранённые данные в Windows, и только если их нет — покажет окно для ввода.
